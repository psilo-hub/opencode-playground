# Domain-Driven Design

Use ubiquitous language consistently.

Consider:
- Entities,
- Value Objects,
- Aggregates,
- Aggregate Roots,
- Domain Services,
- Repositories,
- bounded contexts.

Keep domain rules near the domain concepts that own them.

Respect aggregate boundaries.

Keep infrastructure concerns out of core domain logic where practical.

Do not introduce DDD patterns mechanically; use them when they clarify domain behavior.
